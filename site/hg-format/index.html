The Clover HG Format

Data movement is the bottleneck — not compute. Up to 5× faster CPU tok/s at ~98–99% full-model accuracy.

Modern inference stalls waiting on memory wires, not arithmetic units. Clover’s Hadamard-Grouped (HG4-16R-OP & K31H) format rotates every 128-weight block through a column-balanced Fast Walsh–Hadamard Transform (FWHT-128) into a 16-row lane-interleaved SIMD layout (4.125 bpw), pairs weights with lossless precomputed operator sidecars (HG4OP001), and streams directly into stateful C11 kernels with zero GPUs, zero CUDA, and zero PyTorch at runtime.

Why HG achieves ~98–99% accuracy at a fraction of the bytes

Naive 4-bit or 2-bit quantization clips sharp activation and weight outlier channels, collapsing reasoning on math and formal proofs. Applying a column-balanced 128-point Fast Walsh–Hadamard rotation (FWHT-128) spreads every outlier across 128 coordinates into an i.i.d. Gaussian distribution — letting a 1-cycle SIMD 15-point Lloyd–Max lookup table (LUT16) recover 8× lower perplexity drift than Q4_0.

Under the hood: the 5-stage production conversion & C11 runtime pipeline

Stage 1 — Optional C11 OpenMP Fast Packer (60–100× Faster on 35B–2.8T Checkpoints)

For multi-hundred-gigabyte checkpoints, compile hg4_fast_packer.c. It accelerates FWHT-128, 5-point guarded FP16 Lloyd–Max scale search, and 128-step Cholesky LDLQ error feedback across all CPU cores (converting all 40 layers × 256 experts of Clover-35B-A3B in 11.9 minutes on 1 CPU with zero disk staging).

git clone https://github.com/santhoshsathish94/clover-framework.git
cd clover-framework
gcc -O3 -march=x86-64-v3 -mavx2 -mfma -f16c -fopenmp -fPIC -shared \
  clover-ai-system/src/models/clover-35b-a3b/hg4_fast_packer.c \
  -lm -o clover-ai-system/src/models/clover-35b-a3b/libhg4_fast_packer.so

Stage 2 — Column-Balanced FWHT-128 + HG4-16R Packing (4.125 bpw)

Each 2D weight matrix is padded to [16·⌈R/16⌉, 128·⌈K/128⌉], pre-conditioned by column-RMS Rademacher diagonal D-1, rotated by FWHT-128, quantized to the 16-level Gaussian codebook with 1 FP16 scale per 128 weights (4.125 bpw), and interleaved across 16 output rows (HG4R). Norms, biases, and SSM parameters stay in exact FP32 inside passthrough.safetensors.

Verification gate: convert_to_hg.py --verify checks Hadamard-domain matmul parity (hg4_mean_cosine ≥ 0.995) and records every tensor’s SHA-256 & shape in hg_manifest.json.

Stage 3 — MoE Routed Experts: Full HG4-16R (≤120B) or Hybrid K31H (1T+)

  • Models up to ~120B (fit in 64–128 GB RAM): Keep --moe-cold-bits 4 so all routed experts stay in HG4-16R and mmap directly into RAM.
  • Trillion-parameter MoEs (1T–3T): Pass --moe-cold-bits 2 --hot-experts 42 (or use the dedicated streaming packer convert_kimi_k31_full_hg4.py) to pin hot experts in DDR5 HG4-16R and stream cold tail experts in 2.125-bpw HG2-16R from NVMe.

Stage 4 — Lossless precomputed_ops/ (HG4OP001)

Both convert_to_hg.py and precompute_hg4_operators.py emit Hadamard-rotated FP32 MoE router gates (Wgate D-1 H128), RoPE/YaRN tables, and SSM exponential decays into precomputed_ops/ with Top-K Jaccard == 1.000000.

Stage 5 — Stateful C11 SIMD Engine & Bit-Exact Speculative Verification

Compile the C11 runtime engine with -ffp-contract=off (lfm3_hg4_engine.c, clover35b_hg4_engine.c, nemotron_hg4_engine.c, or kimi_k31_hg4_engine.c) so Scalar, AVX2, AVX-512, and ARM64 NEON produce memcmp == 0 bit-identical matmul outputs.

gcc -O3 -ffp-contract=off -march=x86-64-v3 -mavx2 -mfma -fopenmp -fPIC -shared \
  clover-ai-system/src/models/clover-35b-a3b/clover35b_hg4_engine.c \
  -lm -o ./clover35b-full-hg4/libclover35b_hg4_engine.so
