The Clover HG Format

Data movement is the bottleneck — not compute. Run 2B to 2.8T models on CPU with ~98–99% accuracy.

Modern inference stalls waiting on memory wires, not arithmetic units. Clover’s Hadamard-Grouped (HG4-16R-OP & K31H) format rotates every 16-weight block through a fast Walsh–Hadamard Transform (WHT-16) before quantizing, pairs weights with lossless precomputed operator sidecars (HG4OP001), and streams directly into stateful C11 AVX2+FMA kernels with zero GPUs, zero CUDA, and zero PyTorch at runtime.

Why HG achieves ~98–99% accuracy at a fraction of the bytes

Naive 4-bit or 2-bit quantization clips sharp activation and weight outlier channels, collapsing reasoning on math and formal proofs. Applying an orthogonal 16-point Walsh–Hadamard rotation (H16) spreads every outlier evenly across 16 coordinates before rounding — and reverses the rotation in registers with 64 additions and zero multiplications.

How to convert any open-weight model to HG format

Whether your model is a 2B dense hybrid, a 120B Mamba-MoE, or a multi-trillion-parameter MoE that exceeds RAM, the conversion runs entirely on CPU with OpenMP and mmap — no GPU required.

Step 1 — Compile the C11 .safetensors Hadamard Packer

Clone clover-framework and compile hg4_fast_packer.c. It memory-maps .safetensors shards directly, applies 16-point Walsh–Hadamard block transforms across all OpenMP threads, and writes aligned HG4-16R (4.25b) or HG2-16R (2.25b) tiles.

git clone https://github.com/santhoshsathish94/clover-framework.git
cd clover-framework
gcc -O3 -march=x86-64-v3 -mavx2 -mfma -fopenmp -fPIC -shared \
  clover-ai-system/src/models/clover-35b-a3b/hg4_fast_packer.c \
  -lm -o clover-ai-system/src/models/clover-35b-a3b/libhg4_fast_packer.so

Step 2 — Pack Trunk, Attention & Shared Experts into HG4-16R (4.25 bits/w)

Every weight matrix whose inner dimension K is a multiple of 64 is multiplied on the right by block-diagonal (1/4) H16 and symmetric-quantized in groups of 64 (32 packed bytes + 1 FP16 scale = 34 bytes per 64 weights = 4.25 bits/weight). Norms (RMSNorm / LayerNorm), router gates ([E, H]), and recurrent SSM parameters (A_log, dt_bias) stay in exact FP32.

# Example: Full 40-layer HG4-16R conversion (Clover-35B / Qwen3.5-MoE / Dense Transformers)
python3 clover-ai-system/src/models/clover-35b-a3b/convert_clover35b_full_hg4.py \
  --src /path/to/hf-safetensors-dir \
  --dst ./my-model-hg4 \
  --threads 16

Verification gate: Per-layer output cosine similarity against BF16 reference must satisfy cos ≥ 0.996 before proceeding to Step 3.

Step 3 — Pack MoE Routed Experts: Full HG4-16R (≤120B) or Hybrid K31H (1T+)

Choose the layout that matches your target RAM budget:

  • Models up to ~120B (fit in 64–128 GB RAM): Pack all routed experts in HG4-16R (4.25 bits/w) and mmap them into RAM.
  • Trillion-parameter MoEs (exceed RAM, e.g. 1T–3T): Calibrate router activation frequency on 256 general prompts (or rank by router gate L2 norm), pin the top H hot experts/layer (e.g. 42 / 896) in DDR5 HG4-16R, and stream the remaining cold experts in 2.25-bit HG2-16R from NVMe via convert_kimi_k31_hybrid_92l.py.
# Stream-download & pack a 1T-3T MoE in bounded disk space (2 shards in /dev/shm at a time):
python3 clover-ai-system/src/models/kimi-k3/convert_kimi_k31_hybrid_92l.py \
  --repo-id moonshotai/Kimi-K3.1-Pro \
  --hot-dir ./model-k31h-hot \
  --cold-dir /mnt/nvme/model-k31h-cold \
  --hot-experts 42 --threads 16

Step 4 — Generate Lossless precomputed_ops/ (HG4OP001)

Run precompute_hg4_operators.py to pre-fold router RMSNorm scales, RoPE / YaRN cos-sin tables, Mamba/GDN/KDA exponential gate tables, and hot-to-global expert index maps into precomputed_ops/.

python3 clover-ai-system/src/models/clover-35b-a3b/precompute_hg4_operators.py \
  --model-dir ./my-model-hg4 \
  --verify-routing-jaccard

Verification gate: Assert min_topk_jaccard == 1.000000 (100.0% lossless routing equivalence).

Step 5 — Compile the Stateful C11 Engine & Verify Speculative Equivalence

Compile the matching C11 engine (lfm3_hg4_engine.c, clover35b_hg4_engine.c, nemotron_hg4_engine.c, or kimi_k31_hg4_engine.c). Each engine exposes a uniform C ABI (*_init, *_cache_reset, *_cache_feed, and speculative *_generate_speculative) consumed automatically by Clover’s OpenAI /v1 gateway.

gcc -O3 -march=x86-64-v3 -mavx2 -mfma -fopenmp -fPIC -shared \
  clover-ai-system/src/models/kimi-k3/kimi_k31_hg4_engine.c \
  -lm -o ./model-k31h-hot/libkimi_k31_hg4_engine.so

Verification gate: Run two passes with shuffled OpenMP schedules and with draft_k=0 vs. draft_k=4; assert memcmp == 0 and 100% token-ID equality.
