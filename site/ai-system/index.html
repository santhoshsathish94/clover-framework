The simpler v6.0 4-Part Clover System

Desktop, Android Mobile, and Web Studio all share the exact same codebase (clover-ai-system/studio/clover/) and run the same four-part steerable loop.

Part 1 · AGENTS.md

1. Human Steering & Epistemic Boundaries

Enforces Context → Direction → Execution → Outcome → Growth in code, pauses with STOP_AND_ASK before irreversible or underspecified actions, and applies a Tier-0 tool-exposure gate so small 2B models are never flooded with unrequested planning schemas.

Part 2 · mcp.json

2. Computed 0B Specialists First

Never asks neural weights to guess what an algorithm computes exactly: built-in x-cruncher big-integer arithmetic (A×B, A^B past 6,000+ digits, N!, BBP hexadecimal π), a 0B Periodogram + Split-Conformal forecaster (<50 ms CPU), a 0B Defeasible Rule Resolver, and AST code checks — plus optional HG4 GPU specialists over MCP 2.0.

Part 3 · <task_id>.md

3. Durable Task Context & Private Git Memory

Writes human-readable <task_id>.md context records and stores sessions, verified outcomes, and encrypted credentials locally on your own device (Windows DPAPI / Android KeyStore) with optional sync to your own private GitHub repository (Privacy Policy).

Part 4 · Todo & Telemetry

4. Prerequisite-Gated Todo & Live Metrics Ledger

Tracks multi-step dependencies in SQLite (todos + todo_deps) and records live telemetry (GET /api/clover/metrics): which models and tools are actually used vs. idle, measured decode tok/s (p50/p95/max), cycle retries, and Cycle-2 self-repair signals.

Set up one model — or the full Clover AI System — on your own hardware

Inside Settings → Model → Clover System Setup (and right from first launch via Choose models / Use server), you can select a single model, a custom subset, or the complete Clover AI System across your device and any GPU servers you provide.

Honest interactive hardware gate: Small models and 0B computed tools run interactively on any phone, laptop, or CPU server with zero GPUs. Big models require GPUs to run at interactive speed — if a machine is CPU-only or lacks the required GPU VRAM, Studio automatically skips those models and tells you the exact minimum server needed rather than letting a model crawl at <1 tok/s.
