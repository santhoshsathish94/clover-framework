AI Studio

One system. Any open-weight model. Your phone, laptop, VS Code, or server.

An outcome does not come from which model you use. It comes from the system around it. Clover AI Studio wraps any open-weight model in local memory, relationships, verified tools, JEPA world-model planning, and multi-cycle AGENTS.md Outcome verification — running LFM3-Omni-2B (2B), Clover-35B-A3B (35B-A3B Block Diffusion MoE), Nemotron 3.5 Super VL (120B-A12B), and Kimi K3.1 Pro (2.8T MoE) across Windows, Android, Web, and VS Code Copilot Chat.

How the Clover system works

Semantics sits at the center. Three supporting components gather memory, relationships, and tools; three core stages run the model, plan in latent space, and decode verified answers.

Center · Semantics
Reads your intent, selects only the needed tools, blocks unauthorized vault paths, and labels every answer by how it was verified.
CSI · Language Parser
Parses grammar, verb morphology, and negation so declined tools are never called and unverified action claims are caught.
PPL & CPSL · Learning
Learns your personal habits locally (PPL) and optionally syncs stripped, Ed25519-signed shared-core strategies across installations via Google OIDC (CPSL).
C1 · Inference
Runs the active open-weight model (LFM3-Omni-2B, Clover-35B-A3B, Nemotron 3.5 Super VL, or Kimi K3.1 Pro) with Direction B zero-writeback memory caching.
C2 · Plan & JEPA
Projects continuous <latent> thought vectors with HybridAgent & JEPA / RPRE world-model planning, and runs up to 3 autonomous AGENTS.md Clover Cycle verification passes per turn.
C3 · Decode
Predicts 11 hierarchical concept levels in parallel and decodes strictly inside the active model’s native vocabulary.
S1 · Memory
Saves sessions, execution logs, outcomes, and learned notes in a 5-stage local Git repository with optional private GitHub sync.
S2 · Relationships
Combines symbolic Ontology GraphRAG, multimodal MJEPA recall, and the 11 foundational papers with scenario-gated recall of your earlier chats.
S3 · Tools & Senses
Checks Python/Rust code with a live compiler, connects to OS System Senses (Screenshot, Screen Recorder, Camera, Mic with I-JEPA & Audio-JEPA), and drives VS Code & Copilot under Allow / Ask / Off permissions.

Two-way VS Code & GitHub Copilot integration

Instead of rebuilding an editor, diff viewer, browser, and terminal from scratch, Clover AI Studio integrates directly with VS Code’s open-source workbench and GitHub Copilot Agent loop in both directions (architecture reference).

1. Inside VS Code Copilot Chat → Clover Engine

clover-local-0.4.0.vsix registers all four Clover models (LFM3-Omni-2B, Clover-35B-A3B, Nemotron 3.5 Super VL, and Kimi K3.1 Pro) directly in VS Code’s Copilot Chat model picker:

  • Shared Integrated Browser (browserViewService): Preserves shared browser tabs (<attachment id="Browser Pages">) and drives open_browser_page, read_page, click_element, type_in_page, navigate_page, screenshot_page, and run_playwright_code with automatic [ref=eN] and pageId resolution.
  • Integrated Terminal (terminalService): Runs and monitors run_in_terminal (sync/async), get_terminal_output, send_to_terminal, and kill_terminal.
  • File Viewer & Language Server: Uses read_file, replace_string_in_file, get_errors, vscode_listCodeUsages, vscode_renameSymbol, and multi-cycle AGENTS.md Outcome verification.

2. Inside Clover AI Studio → VS Code Host

When VS Code is open on your laptop, Clover AI Studio connects over its authenticated local bridge (/api/vscode/*) to use VS Code’s native UI:

  • vscode_editor & vscode_diff: Inspects the active editor tab, cursor selection, and document symbols, or opens a side-by-side visual diff (vscode.diff) before applying changes.
  • vscode_diagnostics: Reads live compiler and linter errors/warnings from VS Code’s Problems panel (vscode.languages.getDiagnostics).
  • vscode_browser & vscode_run: Opens and interacts with pages in VS Code’s Integrated Browser via vscode.lm.invokeTool and runs visible commands in VS Code’s terminal.

Port any open-weight model in five folders + JEPA

Clover is model-agnostic. Every ported model in Santhoshsathish94/clover-ai-studio uses the same folder layout while the Studio app, memory, and tools stay unchanged. Run the entire porting pipeline with one command in porting-models/: ./porting-models/port all --config porting-models/configs/clover-35b-a3b.json --gpus 8.

Faster hardware. Higher accuracy.

Direction B keeps weights in raw bytes until the processor registers and drops clean pages with zero writebacks. Models that normally need data-center clusters run on phones, laptops, and single workstations.
