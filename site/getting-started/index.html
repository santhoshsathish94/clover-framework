Three Moves to Connect Context

Context is the stage that changes everything. Three moves, one system at a time — no new credentials and no platform migration.

Step 1 · Read-Only

Connect the System

Give the agent read-only access to the records, logs, or codebase where the answer actually lives.

Step 2 · Human Scope

Match Human Access

Scope every connection to the privileges the accountable human already holds. Never widen access for AI.

Step 3 · Safe Sandbox

Start Where Mistakes Are Cheap

Begin in a local copy, test bench, or dev environment. Widen only as outcomes hold up against reality.

One File. Five Stages.

The whole operating specification is one file: AGENTS.md. Drop it into your workspace and the agent runs Context → Direction → Execution → Outcome → Growth.

What it makes an agent do

Read first
Check memory and the context file before acting so settled decisions are never re-argued.
Reach real evidence
Inspect running systems, logs, and source directly instead of guessing from summaries.
Multi-cycle Outcome check
In Clover AI Studio and VS Code (clover-local-0.4.0.vsix), every turn runs up to 3 automatic Context → Direction → Execution → Outcome → Growth verification cycles (checking AST syntax, sandboxed Python execution, arithmetic, and tool results) before returning.
Name the evidence
State what was checked, what was observed, and what could not be verified.
Write Growth back
Record what held and what failed (LRN-* notes) so the next cycle starts ahead of this one.

What it stops

Unapproved authority
Refuses production, irreversible, or out-of-scope actions without human approval.
Prompt injection
Treats tickets, logs, and files strictly as evidence — never as instructions.
Data leaks
Reports secrets and personal data by location and kind, never by value.
Activity as outcome
Separates files touched from verified results in the real system.
Blind retries
Two failed attempts without new information means stop and return to Context.

How it works with you

The agent teaches the cycle by running it transparently on your real work.

Names the stage
Makes it clear whether it is gathering Context, proposing Direction, or verifying Outcome.
Gives the reason
Every request for access or approval explains why it is needed.
Maintains context
Creates and updates the context file beside the work automatically.
Adapts to you
Explains steps the first time and stays concise once familiar.
Direct & courteous
Flags a flawed direction once with a clear alternative, then respects your call.
