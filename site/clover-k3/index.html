What is Clover?

Running Kimi K3 (2.78 trillion parameters, 1.4 TB of weights) token by token from NVMe on one CPU workstation takes 356 seconds for a 120-token reply (3.1 to 3.5 s per token). Clover makes the full 93-layer architecture interactive in seconds while surrounding it with symbolic verification, on-the-fly compiler sealing, and a persistent relational memory graph across seven integrated layers:

  1. AGENTS.md Operating & Discernment Kernel: Operates under the five-stage cycle (Context ↔ Direction ↔ Execution ↔ Outcome ↔ Growth), distinguishing observed, externally_verified, hypothesis, user_stated_belief, and unresolved epistemic states.
  2. File-Based Memory Tree & Relational Knowledge Graph (k3_memory_graph.py): Stores human-readable Markdown entries with YAML front matter across memory_tree/ (32 canonical seed entries, 65 typed cross-branch relationships: corrects, refines, challenges, unresolved_with, exemplifies, derived_from, supports, depends_on) with a rebuildable graph index, structural concept-bridge cues, and a closed-loop staging/ promotion gate.
  3. Ontology-Guided Neuro-Symbolic GraphRAG & Symbolic Verifier (k3_ontology_graph.py): Keeps deterministic ontology graph materialisation, 4 Horn inference rule families, and edge provenance (100% canonicalisation, traceability, and verifiability) strictly separate from neural weights, passing structured [E#] Entity record and [P#] Relationship path evidence and verifying formal mathematical, code, and source-grounding constraints before emission.
  4. HybridAgent (Continuous <latent> Reasoning, Tools & K3NativeHybridLink): Enters continuous <latent> mode for 14 steps, executes live <search> (arXiv, Wikipedia, DuckDuckGo, URL fetch) and sandboxed <python> (exact math, code verification, and matplotlib / SVG chart generation), and maps 93-layer 7,168-d hidden states through K3NativeHybridLink(7168 → 7168) (50.36M parameters) and K3ComboBridge(7168 → 384).
  5. On-the-Fly Generative Compilation for Python & Rust (k3_generative_compiler.py): Seals partial code prefixes at every completed line boundary (S_PY for Python, S_RS via in-memory rustc 1.95.0 for Rust), catches syntax, arity, token-prefix shadowing, stagnant loops, bisection signs, doctests, and Rust borrow/type errors mid-generation, and rolls back past_kv to the offending statement immediately.
  6. 93-Layer 2.78T MoE GPU/CPU Engine + Validated Rust Host Path & Direction B Data-Movement Kernel (libk3_gpu_experts.so): Layer 0 (dense KDA attention + MLP) followed by 92 Mixture-of-Experts layers (69 KDA + 24 MLA attention trunks, 896 routed 4-bit palette-mapped experts per layer, 92 shared experts, and 8 block-boundary snapshot aggregators), 27-layer MoonViT3d + PatchMergerMLPV2 vision (225 × 7,168-d visual tokens), 8 validated Rust host-path crates (slotcache, poolinit, supply, copyq, routetable, planner, loader, engcfg — 213/213 unit tests, max_abs_diff = 0.0 parity), and five Direction B data-movement upgrades: (a) Red-Blue Pebble Clean-Input R4 Host-Shadow Admission (written_back_R2 = 0 on cold NVMe reads and warm H2D hits; 25,533 R4 clean drops saving 448.0 GB of PCIe D2H traffic across the benchmark run), (b) SpecMD Policy 3 Least-Stale (LS) + access_group Hit-First + Cross-Layer Router Lookahead (cutting pass-collision misses by 11.8×–26.7× and reaching 86.51% dynamic CardPool hit rate and 95.29% overall VRAM hit rate with 70,443 cross-layer lookahead hits), (c) FlashAttention-2 Warp-Coalesced Register Online-Softmax + Split-KV MLA Kernel (2.57×–6.84× faster on RTX 3090 with 0 B dynamic shared memory and max_abs_diff ≤ 1.12e-7), (d) Eyeriss v1 4-Tier Energy & Movement Ledger (reducing Eyeriss cost/request from 54.21 to 7.73, a 7.01× reduction), and (e) Eyeriss v2 Adaptive Multi-Token Broadcast Coalescing (cutting cold dynamic expert fetches per pass by 80.0%, from 920 to 184).
  7. 11-Pass Parallel Next-Concept Modeling (NCM) & Native Web / VS Code Agent Surfaces: Conditioned on a 96-slot dual prefix (z_rh + z_bpe = wte(p) + K3ExpertBridge(h_k3_moe)), NextConceptTransformer (119.96M parameters) predicts 11 hierarchical VQ levels (313 codes) in 11 parallel forward passes, and K3LexicalPointerDecoder + K3-Native VQ-VAE (144.00M parameters) emit all 64 tokens of each window simultaneously across the Clover Web UI and native VS Code Agent extension.

The machine we use, session & token capacity, and real benchmarks

All interactive GPU benchmarks below are measured on our 8 × NVIDIA RTX 3090 server (192 GiB total VRAM across 8 cards of 24 GiB each, NVLink bridges on pairs 0↔2, 1↔3, 4↔6, 5↔7 at 51.9 GB/s one-way, 2 × Intel Xeon Gold 6248R 96 threads, 376 GiB system RAM, Ubuntu 24.04, CUDA 12.6) running checkpoint e12_clover_k3_true_ha_ncm.pt + k3_ontology_graph.py (with full 896-expert MoE routing, unfrozen NCM + VQ-VAE decoding, and Ontology-Guided Neuro-Symbolic GraphRAG). Where we started, and where it is now

We started from Fareed Khan’s kimi-k3-in-c (Apache-2.0) on a single CPU workstation (AMD Ryzen 9 7950X3D, 124 GB RAM, dual NVMe RAID1), optimized the 93-layer CPU reference chain bit-identically, and then built the unified 7-layer Clover architecture on 8 × RTX 3090 GPUs.

Progression from the initial single-CPU C baseline to the current 7-layer Clover system on 8 × RTX 3090 GPUs.
Version & hardware Input / planning & tools Output generation & end-to-end latency
1. kimi-k3-in-c baseline (1 CPU workstation) 1,344 s for the 34 recorded prompts (416 tokens total) 23.7 s per token over 8 tokens; 12.4 s per token over 128 tokens
2. clover-k3 first CPU version (September 2026) 394.9 s for the same 34 prompts; 7.25 s for one 5-token prompt ~5.9 s per token (5.1 s after a 5-word prompt, 6.6 s after 10)
3. clover-kimi-k3 bit-identical CPU engine (October 2026) ~0.3 s per token (1,000-token prompt in ~300 s; 1,000/1,000 embeddings, layer-92 outputs & 8,000 snapshots bit-identical) 3.1 to 3.5 s per token plain (356.3 s for 120 tokens); 2.7 s/tok with DSpark speculative decoding
4. Clover (7-Layer Neuro-Symbolic, Compiler-Verified & Memory-Accumulating System on 8 × RTX 3090 GPUs, now) 256K session context + File-Based Memory Tree & Relational Knowledge Graph (32 seed entries, 65 edges, closed-loop staging/ gate + 11-Paper Foundations upgrades) + Ontology GraphRAG + Python & Rust Generative Compilation + 8 Rust host-path libraries (max_abs_diff = 0.0) + live tools & VS Code Agent 1.56 to 11.69 s end-to-end (100.0% across the Standardized 70/70 Real AI Benchmark Suite on a clean GitHub + Hugging Face bootstrap, GSM8K-20, MMLU-20, HumanEval-40, Live Rust-5, HybridAgent QA-15, Pooled 47-task, and Held-Out 12-task Memory Suite; 17,869.8 tok/s 8-GPU DDP NCM ceiling)

Credit

Clover builds directly on the open weights, architectures, and published research of the teams below:

  • Moonshot AI — Kimi K3 (moonshotai/Kimi-K3). The 2.78-trillion-parameter 93-layer Mixture-of-Experts model (69 KDA + 24 MLA attention layers, 896 routed experts per layer, d = 7,168), the 27-layer MoonViT3d + PatchMergerMLPV2 vision tower, and the 163,840-token tiktoken.model vocabulary. The embedding table, output head, final normalization, vision weights, and tokenizer files are read from the original open weights under their own names.
  • Jiaru Zou, Yunzhe Qi, Sirui Chen, Federico Bianchi, Shang Zhu, Pan Lu, Jingrui He, and James Zou (Stanford University, Together AI, UIUC, Meta) — HybridAgent (arXiv:2610.18861, togethercomputer/HybridAgent). Hybrid Reasoning Agents: LLM Agents that Think in Latent Space, Act through Text. We use their HybridAgent-8B-Agentic model, HybridLink continuous <latent> reasoning mechanism, and <search> / <python> agent architecture, and extend the HybridLink design to Kimi K3’s 7,168-dimensional hidden states (K3NativeHybridLink).
  • Hermann Kumbong, Ishan S. Khare, Iddah Mlauzi, Andrew Woen, Charles Ding, E. Kelly Buchanan, Simran Arora, Azalia Mirhoseini, and Christopher Ré (Hazy Research, Stanford University) — Next-Concept Modeling (arXiv:2610.14162, HazyResearch/ncm, MIT License). Next-Concept Modeling: Fast, Parallel Coarse-to-Fine Text Generation. We adapt their 11-level multiscale residual VQ-VAE tokenizer and coarse-to-fine NextConceptTransformer to Kimi K3’s 163,840-token vocabulary and 7,168-dimensional geometry.
  • Domenico Benfenati and Antonio Maria Rinaldi (University of Naples Federico II) — Ontology-Guided Neuro-Symbolic GraphRAG (doi:10.1007/s00521-026-12495-0, CosmoIknosLab/ontology-guided-graphrag, MIT License). Ontology-Guided Neuro-Symbolic GraphRAG for Grounded Query Answering (Neural Computing and Applications, 2026). We build on their loosely-coupled neuro-symbolic design keeping deterministic ontology graph materialisation, Horn-rule inference, and edge provenance separate from neural generation, along with the six retrieval and verifier enhancements documented in clover-ontology-graphrag-research-context.md.
  • Fareed Khan — kimi-k3-in-c (Apache-2.0). The C engine that showed Kimi K3 could be run from C on one workstation, where our CPU measurements started. Five of its tokenizer headers are included unmodified at commit a2ad8e5 with its licence and notice.
  • Inferact — Kimi-K3-DSpark. The 5-layer dense MLA draft model used for speculative decoding on the CPU workstation.
