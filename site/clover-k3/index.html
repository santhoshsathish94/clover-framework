Clover Kimi K3: Kimi K3 + HybridAgent + Next-Concept Modeling (NCM)

Clover Kimi K3 combines three systems into one unified engine: Kimi K3 (Moonshot AI’s 2.78-trillion-parameter, 93-layer Mixture-of-Experts model with d = 7,168, 163,840 vocabulary, and 27-layer MoonViT3d vision), HybridAgent (continuous <latent> reasoning, live web/arXiv search, Python code & chart execution, and our Kimi-K3-native K3NativeHybridLink 7,168 → 7,168), and Next-Concept Modeling (NCM) (an 11-level hierarchical VQ-VAE and pointer decoder that generates each 64-token Kimi K3 window in 11 parallel passes instead of token by token).

What is Clover Kimi K3?

Running Kimi K3 (2.78 trillion parameters, 1.4 TB of weights) token by token from NVMe on one CPU workstation takes 356 seconds for a 120-token reply (3.1 to 3.5 s per token). Clover Kimi K3 makes the full 93-layer architecture interactive in seconds by uniting three components in Kimi K3’s native 163,840-token vocabulary and 7,168-dimensional hidden space:

  1. Kimi K3 (93-Layer 2.78T MoE Backbone + MoonViT3d Vision): Layer 0 (dense KDA attention + MLP) followed by 92 Mixture-of-Experts layers (69 KDA linear-attention trunks + 24 MLA full-attention trunks, 896 routed 4-bit palette-mapped experts per layer with top-16 selected per token, 92 shared experts, and 8 block-boundary snapshot aggregators) plus the 27-layer MoonViT3d + PatchMergerMLPV2 vision tower (225 × 7,168-d visual tokens).
  2. HybridAgent (Continuous <latent> Reasoning, Tools & K3NativeHybridLink): Instead of thinking only in slow surface text, the agent enters continuous <latent> mode for 14 steps, executes live <search> (arXiv, Wikipedia, DuckDuckGo) and sandboxed <python> (exact math, code verification, and matplotlib / SVG chart generation), and maps Kimi K3’s 93-layer 7,168-d hidden states through our trained K3NativeHybridLink(7168 → 7168) (50.36M parameters) and K3ComboBridge(7168 → 384).
  3. Next-Concept Modeling (11-Pass Parallel Coarse-to-Fine Generation): Conditioned on a 96-slot Kimi-K3-native dual prefix (48 continuous K3NativeHybridLink slots z_rh + 48 expert-enriched BPE slots z_bpe = wte(p) + K3ExpertBridge(h_k3_moe)), NextConceptTransformer (119.96M parameters) predicts 11 hierarchical VQ levels ([1, 4, 8, 14, 20, 26, 32, 40, 48, 56, 64] = 313 codes) in 11 parallel forward passes, and K3LexicalPointerDecoder + K3-Native VQ-VAE (144.00M parameters) emit all 64 Kimi K3 tokens of each window simultaneously.

The machine we use, session & token capacity, and real benchmarks

All interactive GPU benchmarks below are measured on our 8 × NVIDIA RTX 3090 server (192 GiB total VRAM across 8 cards of 24 GiB each, NVLink bridges on pairs 0↔2, 1↔3, 4↔6, 5↔7 at 51.9 GB/s one-way, 2 × Intel Xeon Gold 6248R 96 threads, 376 GiB system RAM, Ubuntu 24.04, CUDA 12.6) running checkpoint e11_clover_k3_native_ha_ncm.pt.

How the 8 × RTX 3090 GPUs are partitioned

Zero disk I/O during inference: all 93 Kimi K3 trunks and 3,312 highest-prior 4-bit experts stay permanently in GPU VRAM.
GPUs VRAM used What runs on them
cuda:0 .. cuda:5 (6 GPUs) 113.5 GiB (18.3–19.7 GiB / card) All 93 Kimi K3 Trunks (trunk-0..92, 52.7 GiB: 69 KDA + 24 MLA attention layers, 92 routers, 92 shared experts, 8 snapshot aggregators) + all 92 MoE Expert Layers (3,312 resident 4-bit palette-mapped experts = 58.1 GB) + Layer-93 Final Tail (libk3_gpu_experts.so).
cuda:6 (1 GPU) 17.2 GiB / 24 GiB CloverK3AgentEngine (e11_clover_k3_native_ha_ncm.pt): HybridAgent-8B-Agentic planner + LiveWebSearchTool + PythonTool + K3NativeHybridLink(7168→7168) + K3ComboBridge + K3ExpertBridge + NextConceptTransformer (NCM) + K3LexicalPointerDecoder.
cuda:7 (1 GPU) 19.3 GiB / 24 GiB K3MultimodalChatEngine: Kimi K3’s 27-layer MoonViT3d + PatchMergerMLPV2 (225 × 7,168-d visual tokens in 42 ms) + Qwen3-VL-8B-Instruct + HybridLink + NCM decoder.

What bounds response speed and token capacity on this machine: Parallel NCM generation is the fastest stage (260–292 tok/s with MBR8 on 1 GPU; 17,869.8 tok/s across 8 GPUs). End-to-end latency on this server is bounded by (1) autoregressive window-plan generation in HybridAgent-8B-Agentic on a single cuda:6 card (~18 ms/token), (2) sequential stage handoff of the 93 Kimi K3 layers across cuda:0..5 over PCIe Gen 3 x16 / NVLink (~1.26 s per pass), and (3) the 192 GiB total VRAM budget, which holds all 93 trunks (52.7 GiB) plus the top 3,312 4-bit experts (58.1 GB) in GPU memory with zero disk I/O.

Sessions, context limit, clubbing, and token capacity

Capability Limit / capacity on this machine How it works without mixing sessions
Context limit per session 262,144 Kimi K3 tokens (256K)
(> 250k minimum)		 Every session indexes conversation turns and uploaded files (PDF, DOCX, Markdown, CSV, JSON, code, image/video vision analysis, audio) into ~240-token chunks (tokenized via libk3tok.so). While under 262,144 tokens, chunks stay verbatim; only when a session reaches the full 262,144-token limit does the engine automatically summarize older multi-paragraph blocks into clear, smaller sentences in simple words so key facts, numbers, and identifiers are retained without dropping history.
Concurrent sessions Unlimited stored sessions;
up to 8 active sessions clubbed per batch		 Each browser tab/user gets an isolated session_id persisted to disk. Requests arriving within the 1.0-second dynamic batching window (BATCH_PAUSE_S = 1.0) are automatically clubbed into one GPU batch.
Clubbing prompts without mixing Up to 8 prompts / batch
(24–32 windows = 1,536–2,048 K3 output tokens per batch pass)		 Prompts are stacked along the batch dimension ([B, seq_len] with left-padding and per-row attention_mask in planning, and [W_tot, 96, 384] with isolated per-window vocabulary masks in NCM), never concatenated in sequence. Verified across clubbed batches with 0 leaked tokens between sessions.
Input & output token capacity 16,000 input tokens / GPU (128,000 across 8 GPUs);
1,536 K3 output tokens / response (24 windows × 64 tokens)		 A single NCM window emits up to 64 Kimi K3 tokens in 11 passes. In 8-GPU DDP mode (256 windows = 16,384 token capacity), all 8 RTX 3090s emit 11,464 Kimi K3 tokens in 641.5 ms (17,869.8 emitted tok/s; 25,539.0 capacity tok/s).

Where we started, and where it is now

We started from Fareed Khan’s kimi-k3-in-c (Apache-2.0) on a single CPU workstation (AMD Ryzen 9 7950X3D, 124 GB RAM, dual NVMe RAID1), optimized the 93-layer CPU reference chain bit-identically, and then built the 8 × RTX 3090 GPU architecture uniting all 93 Kimi K3 layers with HybridAgent and Next-Concept Modeling (NCM).

Progression from the initial single-CPU C baseline to the current 8 × RTX 3090 Clover Kimi K3 + HybridAgent + NCM system.
Version & hardware Input / planning & tools Output generation & end-to-end latency
1. kimi-k3-in-c baseline (1 CPU workstation) 1,344 s for the 34 recorded prompts (416 tokens total) 23.7 s per token over 8 tokens; 12.4 s per token over 128 tokens
2. clover-k3 first CPU version (September 2026) 394.9 s for the same 34 prompts; 7.25 s for one 5-token prompt ~5.9 s per token (5.1 s after a 5-word prompt, 6.6 s after 10)
3. clover-kimi-k3 bit-identical CPU engine (October 2026) ~0.3 s per token (1,000-token prompt in ~300 s; 1,000/1,000 embeddings, layer-92 outputs & 8,000 snapshots bit-identical) 3.1 to 3.5 s per token plain (356.3 s for 120 tokens); 2.7 s/tok with DSpark speculative decoding
4. Clover Kimi K3 + HybridAgent + NCM (e11, 8 × RTX 3090 GPUs, now) 256K session context; continuous <latent> reasoning + live <search>, <python>, matplotlib charts & MoonViT3d vision 1.56 to 11.69 s end-to-end (60.5 K3 tok/s E2E, 76.6 tok/s across all 93 K3 GPU layers, 8.30–8.86 s/session clubbed across 4 sessions, 17,869.8 tok/s 8-GPU DDP NCM ceiling)

Credit

Clover Kimi K3 builds directly on the open weights, architectures, and published research of the teams below:

  • Moonshot AI — Kimi K3 (moonshotai/Kimi-K3). The 2.78-trillion-parameter 93-layer Mixture-of-Experts model (69 KDA + 24 MLA attention layers, 896 routed experts per layer, d = 7,168), the 27-layer MoonViT3d + PatchMergerMLPV2 vision tower, and the 163,840-token tiktoken.model vocabulary. The embedding table, output head, final normalization, vision weights, and tokenizer files are read from the original open weights under their own names.
  • Jiaru Zou, Yunzhe Qi, Sirui Chen, Federico Bianchi, Shang Zhu, Pan Lu, Jingrui He, and James Zou (Stanford University, Together AI, UIUC, Meta) — HybridAgent (arXiv:2610.18861, togethercomputer/HybridAgent). Hybrid Reasoning Agents: LLM Agents that Think in Latent Space, Act through Text. We use their HybridAgent-8B-Agentic model, HybridLink continuous <latent> reasoning mechanism, and <search> / <python> agent architecture, and extend the HybridLink design to Kimi K3’s 7,168-dimensional hidden states (K3NativeHybridLink).
  • Hermann Kumbong, Ishan S. Khare, Iddah Mlauzi, Andrew Woen, Charles Ding, E. Kelly Buchanan, Simran Arora, Azalia Mirhoseini, and Christopher Ré (Hazy Research, Stanford University) — Next-Concept Modeling (arXiv:2610.14162, HazyResearch/ncm, MIT License). Next-Concept Modeling: Fast, Parallel Coarse-to-Fine Text Generation. We adapt their 11-level multiscale residual VQ-VAE tokenizer and coarse-to-fine NextConceptTransformer to Kimi K3’s 163,840-token vocabulary and 7,168-dimensional geometry.
  • Fareed Khan — kimi-k3-in-c (Apache-2.0). The C engine that showed Kimi K3 could be run from C on one workstation, where our CPU measurements started. Five of its tokenizer headers are included unmodified at commit a2ad8e5 with its licence and notice.
  • Inferact — Kimi-K3-DSpark. The 5-layer dense MLA draft model used for speculative decoding on the CPU workstation.
