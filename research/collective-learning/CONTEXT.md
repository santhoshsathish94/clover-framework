## 1. What This Research Is

Clover already has two foundational capabilities on device:
1. **Clover Semantic Interface (`CSI v0.1r3`, [`research/semantic-interface/`](../semantic-interface/CONTEXT.md)):** A frozen, model-independent language-understanding interface (Dictionary / Morphology / Grammar / Semantics) that extracts structured propositions, roles, polarity, mood, and verified lemmas across any LLM backbone.
2. **Personal Process Learning (`PPL`, [`research/personal-process-learning/`](../personal-process-learning/CONTEXT.md) & [`clover-ai-system/mobile/personal.py`](../../clover-ai-system/mobile/personal.py)):** Per-user experiential learning that adapts to how one individual communicates and prefers answers, stored in a local Git repository with full history deletion (`keep`, `stop`, `delete`).

**Collective Problem-Solving Learning (CPSL)** investigates the open research question connecting them:

> **Can a population of independent Clover installations collectively discover general-purpose problem-solving strategies and semantic patterns from local experiences—without sharing personal data, without centralizing conversations, and without retraining model weights?**

The core scientific principle governing this work is:

> **Clover must learn from people without learning to become those people.**  
> It should discover what is generally useful from their experiences, while preserving what is personally theirs.

## 3. How the 10 Research Areas Map to Clover's Architecture

| Mechanism / Paper | What It Transfers | Role in Clover |
|---|---|---|
| **1. Federated Learning (`FedAvg`, McMahan et al., 2017)** | Dense model weight updates $\Delta W$ | **Not used for core sharing** (heterogeneous models `LFM3` / `Nemotron` / `Kimi K3`, plus sparse lexical gradient leakage). Reserved only if homogeneous adapter training with formal DP is ever needed. |
| **2. Federated Analytics (Wang et al., 2021/2022)** | Structured analytical insights & installation-deduplicated counts | **Used in `collective.py` & `collective_gateway.py`**: local learning runs on device; only de-lexicalized CSI candidate counts are aggregated across distinct installations. |
| **3. Knowledge Distillation in FL (Salman et al., 2025)** | Model-agnostic input–output behavior / symbolic mappings | **Used across Clover's switchable models**: because CPSL shares symbolic `CSI Trigger -> Capability/Strategy` rules, a strategy discovered on `Kimi K3` works immediately on `LFM3-Omni-2B` (mobile/laptop) and `Nemotron`. |
| **4. Voyager Skill Library (Wang et al., 2024)** | Compositional, inspectable multi-step skill programs | **Used in `problem-solving/` rules** (multi-step decompositions like `preflight -> test + format`), upgraded with held-out verification so one user's skill never blindly overwrites another's (`skill.py:65-72` fix). |
| **5. Reflexion Verbal RL (Shinn et al., 2023)** | Explicit reflections from execution/correction feedback | **Used in local observation -> hypothesis formation**, upgraded by abstracting lessons through **CSI propositions & lemmas** so private entities are stripped before transfer (`92.5% -> 0.0%` leak, `63.0% -> 83.0%` transfer). |
| **6. MAML Meta-Learning (Finn et al., 2017)** | Outer-loop validation on disjoint query tasks $\mathcal{T}_i^{\text{query}}$ | **Used in `collective_evaluator.py` (`Gate G3 & G4`)**: local discovery is the inner loop; promotion into the shared core requires passing held-out unseen phrasings and cross-domain query tasks. |
| **7. Swarm Learning (Warnat-Herresthal et al., 2021)** | Peer quorum (`minPeers`) + signed contract & validation | **Used in `Gate G1` (`independent_installations >= 3`) & `core_registry.py`** signed release manifests (`releases/manifest.json`). |
| **8. Privacy & Security in KD-FL (Reguieg et al., 2026)** | Threat-surface analysis of shared non-weight knowledge | **Used in defense-in-depth scrubbing**: proves why abstracting to rules is not automatically private without closed-vocabulary (`OEWN`) gating, k-anonymity quorum, and PII regex scrubbing. |
| **9. Robust Federated Learning (Uddin et al., 2025)** | Defenses against Sybil, label-flipping, and Byzantine poisoning | **Used in `CollectiveGateway` (installation deduplication) + `Gate G2` (cross-user consistency $\ge 0.75$) + `Gate G5` (zero-regression check)**. |
| **10. Privacy Ripple Effects (Borkar et al., ACL 2025)** | Assisted memorization & unlearning removal collateral exposure | **Used in `collective.py` (pre-extraction closed-vocab scrub) & `core_registry.py` (`withdraw_installation`)**: eliminates both weight-level assisted memorization and our newly discovered **symbolic intersection-unmasking ripple effect**. |

## 4. How This Helps Clover (Concrete Integration Path)

1. **Immediate Architectural Bridge Between `CSI` and `PPL`:**
   - Currently in [`clover-ai-system/mobile/semantics.py`](../../clover-ai-system/mobile/semantics.py) and [`personal.py`](../../clover-ai-system/mobile/personal.py), `semantics.interpret()` checks `Runtime.personal` (for that user's validated habits) and otherwise falls back to static `ASKS` regexes.
   - By adding `Runtime.collective` (`core_sync.py`), any opted-in Clover installation (Studio on laptop, S23 mobile app, or K3 server) can load a signed `releases/manifest.json` from `clover-collective` and resolve:
     $$\text{Declined / Safety} \;\succ\; \text{Personal (`Runtime.personal`)} \;\succ\; \text{Collective (`Runtime.collective`)} \;\succ\; \text{Static General (`ASKS`)}$$
2. **Model-Independent Capability Growth Across All Clover Devices:**
   - Because collective rules are expressed in **CSI features (`tok=`, `has=`, `pat=`, `ctx=`)** and **Clover capabilities (`web.search`, `python`, `files.read`, `shell`, or multi-step plans)**, a problem-solving strategy validated on `k3` improves `LFM3-Omni-2B` on a phone or laptop without changing a single model weight.
3. **Inspectable, Auditable, Revocable Growth (`AGENTS.md` §§5, 8, 16):**
   - Unlike weight fine-tuning—where a bad update is opaque and unlearning causes privacy ripple effects—every collective rule in `clover-collective/core/` is a human-readable JSON file with exact evaluation metrics, signed in Git, and cleanly demotable if contributors withdraw consent.

## 5. Honest Boundaries, Limitations & What Remains Open

Following [`AGENTS.md`](../../AGENTS.md) §4 and §11, we state explicitly what this research establishes and what it does not yet cover:
1. **Controlled Simulation vs. Consented Real-User Pilot (`[known]`):**
   - `CPSL-1` ran on `k3` using the real frozen `CSI v0.1r3` parser/lemmatiser/dictionary and the real `PPL` learner across 20 simulated contributor installations and 12 simulated recipient installations. While the linguistic parsing (`en_core_web_trf` + `morph-verb-v1.1` + `OEWN 2025`) and Git registry are real, the 20 contributor personas and 12 collective strategies were constructed for this controlled experiment. Real-world validation requires a consented multi-user pilot.
2. **Mismatch-Masking Limit (`strat_semantic_digest`, `[verified]`):**
   - When a training phrasing contains a secondary cue that causes the baseline interpreter (`B0`) to guess the right intent for the wrong reason (e.g., `"distill the key points of {doc}"` succeeding because of `"points"`), `Learner` records no mismatch and does not extract `"distill"`. Learning positive anchor associations from **confirmations** (when confidence is low or when a novel verb co-occurs with a confirmed outcome) is the natural `CPSL-2` / `PPL-2` improvement.
3. **Multi-Word & Out-of-Vocabulary Technical Terms (`[known]`):**
   - The closed-vocabulary privacy filter (`OEWN 2025` `<Lemma>` + `<Form>`) blocks all private names and identifiers (`0.0%` PII leakage), but also blocks brand-new technical neologisms not yet in `OEWN` unless they are added to a curated domain lexicon.
4. **2B Model Tool-Copy & Search-Query Hygiene (`[verified]` in Stage 5 Live Run):**
   - When `collective` routes `python_interpreter` on a 4-digit multiplication (`1789 * 4321`), the 2B model can occasionally mistype a digit (`17889`) in its generated Python code; `semantics.align()` catches the number mismatch (`"from Python · some numbers not in it"`) and withholds the `verified` badge.
   - When `collective` routes `web_search` on a sentence beginning with a collective strategy verb (`"Corroborate the scientific fact: ..."`), passing the full sentence as the search query can retrieve broad list pages where neighboring numbers distract a 2B model. Stripping the collective trigger prefix from the search query is a natural next refinement.
5. **Worktree Isolation Boundary Kept (`[known]`):**
   - All runtime and research changes live strictly on branch `experiment/collective-learning` inside the dedicated worktrees (`C:\personal\oss\clover-collective-wt` locally and `/opt/clover-k3/collective-wt` on `k3`). The main worktree (`C:\personal\oss\clover-framework`) and the live K3 server (`:8765`) are completely untouched.
