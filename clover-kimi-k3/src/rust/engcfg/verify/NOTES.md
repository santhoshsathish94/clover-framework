# engcfg differential driver (v1 written with the crate; v2 added after the independent mutation check, see "driver v2" in RESULTS.md and the E9 / write-capture / E8 paragraphs below)

**What it is.** `diff_driver.cpp` dlopens a reference (`ref/libengcfg_ref.so`, the engine's own text at 4d8d891 behind the contract) and a candidate (`target/release/libengcfg.so`) with `RTLD_NOW|RTLD_LOCAL` and compares them on random inputs. It changes nothing in the crate, `ref/` or the header. No CUDA, no GPU, no engine.

**Rerun (box `gpu`).** `ssh gpu 'cd ~/rustmig/engcfg/verify && ./build.sh && (ulimit -v 3145728; ./run.sh [CANDIDATE.so] [--only E1,E3 --scale F --keep-going --flip N --seed0 N --e9-vm-mb N])'` (env `REF`, `JOBS` capped at 24, `OUT`; runs at `nice -n 10`). Output: `out/run-<time>/` with `units.log` (raw: `BEGIN scen seed`, `UNIT scen seed cmp chk cases PASS|FAIL|CRASH`, `STAT scen seed key value` branch counters), `stdout.txt` (summary + summed branch statistics), `stderr.txt`, `fail/` (first-difference reports with the case). `./count.sh OUTDIR` recounts units, comparisons and cases from `units.log` with awk. `./asan.sh` rebuilds the reference with ASan+UBSan and runs the same driver against the Rust build (libasan preloaded; reports go to files because the children's stderr is compared). The driver stops scheduling at the first FAIL/CRASH unless `--keep-going`.

**Units.** A unit is (scenario, seed), run by one worker process (at most 24 at once), with its own scratch directory (also its cwd). Anything that can exit, die or register an exit handler runs in a forked child with stderr redirected to a file and its result text in another; everything else captures fd 2 in-process (`dup2` to a file). Exit status, terminating signal, stderr bytes and result text are all compared.

**Scenarios (what is compared, where the inputs come from).**
- **E1 env_int** (60 units x 5000): a variable set to a generated value or unset; value = a list of special strings (whitespace of every C kind and of non-C kinds, signs, `0x10`, `+5`, `+-5`, `1e3`, trailing junk, all the int / long / unsigned-long boundaries +-1, 70-digit strings with leading zeros), random decimal strings with whitespace/sign/junk, random non-NUL bytes; default drawn from {0, 1, -1, INT_MAX, INT_MIN, typical values, random}; every case is also run with the bitwise-flipped default (unset and empty must follow it, anything else must not).
- **E2 settings + pend_cap** (40 x 4000): each of the 13 variables is unset, takes a value from its own list of typical and edge values, or a generated value; K3GPU_ROUTECACHE is a path (65%: random bytes, spaces, high bytes, empty 5%); decoy variables (TRACE, COPYQ, ...) are set to junk; `devices` from {0, 1, 2, 4, 7, 8, 9, 16, -1, -5, INT_MAX, INT_MIN, random}. Every field of `ec_settings` is compared, the `routecache` pointer must be getenv's own pointer in both libraries, `ec_pend_cap` runs on three 64-bit values per case.
- **E3 card_of**: one exhaustive unit (4 layouts x cards -3..12 x layers -300..400, minus the two trap inputs) and 24 units x 100000 random (layout from {0, 1, 2, -1, 100, INT_MAX, INT_MIN}, cards and layers from small ranges, extremes and random 32-bit values).
- **E4 force_routes** (4000 units, one script of 60 calls each): the same script runs in a forked child per library (the once-only warning flag is per process); every call's `sel` buffer (n*top words plus 512 slack words, prefilled with a per-call pattern) is compared block by block, and the stderr of the whole script. Calls are valid ones (counts <= n, sum = n*top, up to 51 experts, random expert ids incl. negative) and mutants of them: counts one short / absent / sum one too high or low / a count above n / empty call / negative counts / a negative count compensating a raise so the writes run past `n*top` / n off by one / `top` in {16, 1, 2, 3, 4, 8, 17} / n in 0..200 / `pos` at 0, size-1, size, size+1, SIZE_MAX / `cur` NULL when it must not be read / layer mismatch.
- **E5 print_summary** (100 x 3000): random `ec_summary` (cards -3..8, 8 cards with ready flags, counters from 0 up to UINT64_MAX and values around 2^32, 2^53, 2^63; doubles: 0, -0, binary ties k/16, decimal near-ties, huge, tiny, denormal, inf, NaN with random payload/sign, random bit patterns); 5% of cases make the sum of `needed` wrap to 0 or a small number; stderr compared byte for byte.
- **E6 selectors, trace, prefill, messages** (60 x 1000, 40% selector, 20% trace, 10% prefill, 30% messages): selector = every component x built/not built x X and X_LIB from lists (unset, empty, cpp, rust, Rust, RUST, padded, `cpp\n`, `1`, random bytes); a child per case compares exit status, stderr and `mode=%d lib=%s`. Trace = 14 paths (unset, empty, /dev/null, a new file, a relative name, missing directory, a directory, `/proc/...`, 5000 characters, 300-character name, non-UTF-8 name, trailing space, `/`), 50% with a file already there holding bytes; compared: status, stderr, whether a regular file exists afterwards, its size and mode. Prefill = calls in {0, 1, 2, 3, 5612, SIZE_MAX, random}. Messages = random `ec_settings` (NULL route cache 10%), calls and pend_cap random 64-bit; selector announce with random lib bytes and NULL.
- **E7 composite configure()** (100 x 1000): three arms per case, each in its own child with a generated environment (13 variables, route cache path, three selector variables mostly valid, LIB variables, trace path), `devices` and the three `built` flags: **A** = the engine's `configure()` text, whole, with stand-ins (ref `ecref_configure`); **B** = the sequence of contract calls documented in `engcfg.h` on the reference library; **C** = the same sequence on the candidate. Compared A vs B (checks the contract is sufficient and the glue right) and A vs C: exit status, signal, all stderr (including the three exit-time summary lines the `atexit` handler prints) and a dump of the settings the run left behind (cards, readers, ..., pend_cap, rc_ok, vq, hook set, ...).
- **E8 out-of-contract deaths**: `card_of(1, 0, 5)`, `card_of(1, -1, INT_MIN+1)`, `force_routes` with n = -1: both libraries must die by a signal (the reference by SIGFPE / SIGABRT, the Rust library by SIGABRT). v2 also compares the text left on stderr: the reference must leave what it is designed to leave (nothing for the SIGFPE, or, for the UBSan build of `asan.sh`, UBSan's own `runtime error: division ...` line; libstdc++'s terminate text naming `std::length_error` for the vector) and the candidate must leave **nothing** (an explicit `abort()`). The last pin is the crate's own design (NOTES.md of the crate), not a sentence of the header; it is what separates the two explicit checks from a Rust panic of the `%` or of the vector size (a panic prints its message before it aborts).
- **E9 force_routes at sizes E4 cannot reach** (v2; 13 units, one fixed case each, seed = case index, started after E7): both libraries run the case in a fresh process (so the once-only warning is the first thing seen), at the same time, each with RLIMIT_AS = `--e9-vm-mb` MB (default 2048; `asan.sh` passes 0 because ASan reserves terabytes of address space). Exit status, signal, stderr and the whole `sel` buffer are compared; beforehand the reference's own result is checked against a hand-worked expectation (warning text, or the dealt buffer), so that a case that stopped showing what it is for fails by itself. Cases: `s32-heavy` (n = 2^22, top 1, 513 experts of count 2^22 plus one count INT_MIN: 2,151,677,952 deals, the dealing counter passes 2^31, every token gets 513 deals so fill counters of 8 bits wrap; buffers of 16 MB; the reference's `sel[j] = 1000 + min(512, j)` is derived by hand), `total32` (5 counts of 2^30: the sum 5*2^30 reads 2^30 = n*top in 32 bits; a candidate that accepts needs a 4 GB `fill` and dies under the limit), `total32neg` (n 0, counts INT_MIN twice: -2^32 reads 0), `ntop32` (n 4096, top 2^20: n*top = 2^32 reads 0), `ntop32neg` (n = top = 46341, one count -2147479015: n*top reads that value in 32 bits), `u8` / `u16` (n = 1, top = 1, 300 / 70,000 deals to one token), `morecounts`, `morecounts-sum-ok`, `counts-without-experts` (more counts than experts), `count-above-n`, `count-above-n-negative` (a count above n with the right sum), `valid-control` (hand-dealt). Not reachable inside the memory bound, stated rather than hidden: a **valid** call with n*top or a sum of counts above 2^31 - 1 needs a buffer of more than 8 GB, so the rejecting direction of the 32-bit mutants (a valid call refused because the width wrapped) is not driven; a fill counter above 2^31 (2^31 deals to one token with n = 1) is not reachable at all.
- **E4 appended calls** (v2): every script ends with six calls from a generator of its own (the first 60 calls are unchanged): one extra count of 0, two extra counts +1 / -1, no experts with one count, a count above n with the right sum, two extra experts of count INT_MIN (the sum is n*top - 2^32), and n = 1 with 257-400 deals to one token; the driver checks that the reference left `sel` alone for the first five kinds and dealt for the last.
- **Write granularity** (v2): the candidate's fd 2 is, in E4 scripts, E5, E6 and E7, one end of an `AF_UNIX SOCK_SEQPACKET` socketpair in the child (message-preserving, one `write` = one message; a `SOCK_DGRAM` pair has no end-of-file, which a reader needs), so every `write(2)` is seen. Rule (`check_writes`): every write of the candidate ends in a newline (a line is never cut), and where the lines are known the number of writes is exact (E5: one per line of the reference's text; E6 messages: 2 and 1). The reference is not held to this: glibc's unbuffered `fprintf` writes a line of more than 128 bytes in several pieces (counted in the `writes.*` statistics, 14,828 of 18,800 sampled E5 cases).

**Counting.** cmp = one reference-vs-candidate equality on a scalar, a string or one block of bytes; chk = a check on one library (E2 pointer identity, E4 reference finished, E5 table line present); cases = random cases generated (E4: calls). `STAT` lines count what the cases reached (see RESULTS.md); they exist because a passing run over inputs that never reach a branch proves nothing about it. `--flip N` makes the N-th comparison of a unit see a perturbed candidate value: a plumbing check that comparison, reporting and exit status fire (used with `--only E1`, `E4`, `E7`); it is not a mutation control.

**Not covered / known weak spots.** See the list in `RESULTS.md` ("mutations a driver could easily miss") and `../NOTES.md` ("Not covered").
