# What Is Still Missing?

After the experiments in this directory, “self-development” can be made a
testable engineering question.

## Working definition

A self-developing system is one whose **validated future capability is partly
produced by its own developmental process**, rather than being completely
specified in advance.

This deliberately avoids claiming consciousness.

## Criteria

| Criterion | Current status |
|---|---|
| Persistent state | Demonstrated |
| Behavioral improvement | Demonstrated in toy domain |
| Capability acquisition | Demonstrated in toy domain |
| Meta-development | Demonstrated in toy domain |
| Objective discovery | Demonstrated as a mechanism |
| Independent validation | Demonstrated in toy domain |
| Self-expansion of capability space | Untested |
| Open-ended development | Untested |
| Developmental identity across model replacement | Demonstrated for scripted workers |
| Subjective experience | Unknown |

The toy domain is a search for coefficients of known functions over a fixed
ladder of five tasks. Every row marked "toy domain" was observed there and
nowhere else. It does not establish that any of these properties survive a task
whose target is not supplied by the experimenter.

The model-replacement row rests on `model_swap_test.py`, run against two local
language models from different families, `llama3.2:1b` and `qwen2.5:0.5b`. The
state carried the trajectory and the second worker inherited the first's open
question. It is conditional: with the order reversed the run fails, because
`qwen2.5:0.5b` returns a well-formed object with `next_question: null` on every
cycle and so leaves nothing to inherit. Neither model supplied independent
evidence, so nothing entered `validated_knowledge`.

## The decisive remaining experiment

Most current experiments still contain a human-designed search space.

For example, we provide:

- the representation
- primitive operators
- mutation rules
- task structure
- evaluator semantics
- resource boundaries

Therefore the system is developing **inside a designed box**.

The next experiment should let the process propose:

1. a new representation
2. new operators over that representation
3. procedures using those operators
4. tests for the procedures
5. evidence that the new representation creates capabilities unavailable in the old representation

The external evaluator must remain independent.

## The strongest test

The cleanest measurement is capability-space expansion:

```
Capability space at T0
        ↓
development
        ↓
Capability space at T1
        ↓
new capabilities impossible or inefficient
under the previous representation
```

If repeated cycles produce validated capabilities that expand the future
search space, we have evidence for genuine computational self-development.

That still does not answer the consciousness question.

It does answer a more tractable question:

> Can a computational process become increasingly capable through a persistent
> developmental loop whose future machinery is partly generated by the loop
> itself?

## Clover connection

This makes Growth precise:

**Growth is not simply remembering the past.**

Growth is when validated experience changes what the system is capable of doing
in the future.

That is the strongest engineering interpretation of:

**Context → Direction → Execution → Outcome → Growth.**
