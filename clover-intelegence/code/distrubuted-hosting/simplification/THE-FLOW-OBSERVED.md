# The flow, observed

The creator's direction for this cycle:

> Observe the complete input-to-output flow without using the expected output token to
> judge or interpret internal computations. Capture what actually happens at every stage,
> including state changes, routing, and intermediate values. Separate observation from
> interpretation and judgment. Let evidence reveal patterns; do not force observations to
> confirm expectations.

The previous cycle used the answer token as its instrument throughout — *does this source
pick 316, does RMS change the answer, is the answer already decided*. Every reading was
therefore a test of my expectation rather than a description of the system. This document
does not do that. Nothing upstream of the head is scored against any token.

The sections below are split deliberately. **Observed** is measurement. **Reading** is
mine and can be discarded without touching the measurements above it.

---

## What was captured

One run of the production fleet on `1008 10484 318 15383 387`, five positions, with
`CLOVER_VECTORS` unrestricted so **every owner writes every local it has** — 94 files,
1.6 GB, plus a full `CLOVER_TRACE`. Nothing was filtered on the way out.

### Observed: what the engine records, from an inventory of the capture

| owner | records | what is there |
|---|---|---|
| 0, the server | 35 | locals 5201–5207, five positions |
| 1 | 620 | no 2003, no 2021, no 3000 |
| 2, 4, 5, 6, 8, 9, 10 … (KDA) | 635–670 | locals 0–9, 20–120, 1000+, 5001–5009 |
| 3, 7, 11, 15 … 91, 92 (MLA) | 575–610 | locals 0–6 then 20–120; **no 7, 8, 9; no 5001–5009** |
| 93, the tail | 13 | 5301–5305, 5310–5317, one position |

Every pod writes a 7168-wide record at **every stage it executes**, so the carried state
is available as vectors at every step rather than as a hash. The record count rises with
depth only because the snapshot slots `1000+k` accumulate.

**Owner 1 records no fold scores and no router weights where all 91 other pods do.** Layer
1 is generated by a different generator (`derive-transformer.mjs`) than layers 2–92. This
is an asymmetry in the instrument; whether it is also an asymmetry in the model is not
established here.

### Observed: what a record is, read off `transformer_process`

```c
clover_vectors_write(LAYER, 0, positions, input, WIDTH);     /* before the loop */
while (sequence->stage) {
    const int executed = sequence->stage;
    transformer_step(...);
    clover_vectors_write(LAYER, executed, positions, sequence->residual, WIDTH);
}
```

- `local 0` is the pod's **input**, written outside the loop. Not a stage.
- `local N ≥ 1` is the residual **after** stage N ran.
- Stage 1 is `memcpy(sequence->incoming, input, …)` — it never touches `residual`. So
  `local 1` is the residual left over from the previous position, and is **0.0000 at
  position 0** because the sequence starts zeroed.
- Stage 2 is `memcpy(sequence->residual, input, …)`. That is where the position's input
  enters the carried state.
- Stage 120 does `positions++` *before* the record is written, so its label is one
  position ahead of its contents. Same vector as `local 119`.

**This corrects a figure I have reported three times.** "636 of 9,956 stages move the
residual" counted locals 0, 1 and 120 — 276 bookkeeping records across 92 pods — as
movement. The honest split at position 4 is **361 changed, 9,319 bit-identical, 276
bookkeeping**. I had already catalogued the stage-120 off-by-one in repository memory and
reintroduced it anyway, which is the third time for that specific bug.

### Observed: the two instruments agree once bookkeeping is removed

The same run also wrote a full `CLOVER_TRACE`, which hashes the residual after every
stage. Counting hash changes along the same sequence at the same position:

| | trace, hash changes | vectors, carried |
|---|---|---|
| local 2 | 92 | 92 |
| local 6 | 24 | 24 |
| local 9 | 68 | 68 |
| local 20 | 85 | 85 |
| local 116 | 92 | 92 |
| local 120 | **91** | counted as bookkeeping |
| **total** | **452** | **361** |

452 − 91 = 361. Two instruments — a 64-bit hash and 7168 floats — built at different
times for different questions, agree exactly on which stages change the carried state.
The trace has no `local 0` record at all, which is why its bookkeeping surplus is one
record per pod rather than three.

### Reading

Of a pod's ~120 stages, exactly **four** change the carried state: the input copy, one
attention stage, the attention fold, and the MoE add. Everything else — including all 80
expert stages — leaves the residual bit-identical, because the expert stages write into
`routed` and `shared_output` and stage 116 is where `residual += routed + shared`.

The residual grows monotonically within a block and collapses at every twelfth pod. The
six largest contractions in 91 transitions are precisely the six block-write pods below
84. The mechanism is in the source and has been since the first implementation
(`if (have_prefix) resid += aout; else memcpy(resid, aout)`), so **this validates the
instrument rather than discovering anything** — which is the useful part: a walk that did
not reproduce it would be wrong.

`local 20` firing 85 times rather than 92 is the same seven pods: where the residual is
replaced rather than added, stage 20 leaves it bit-identical.

Stage 116 has the highest median cosine of any changing stage (0.900) and the smallest
median relative movement (0.54). The attention stages have the lowest (MLA −0.049, KDA
0.219) and move the state by roughly its own length.

## What this does not establish

- **One prompt, five positions, one generated token.** Every number is from a single run
  of `1008 10484 318 15383 387`. Nothing here is a rate or a property of the model.
- **Softmax statistics across rows of different norm are not comparable as confidence.** A
  dot product scales with the vector, so the same direction at twice the length gives a
  sharper distribution. The norm is printed beside every row for exactly that reason. The
  comparison that is sound within a row is entropy against log(163840); across rows, only
  the geometry (norms and cosines) is.
- **Feeding a snapshot to the head is not "what the model would have said at that block".**
  Those vectors have not been through `normalization_apply_rms`, which the measurements
  above show is a reorientation and not a scaling, so they are not on the head's footing.
- **"95 stages leave the residual bit-identical" is not "95 stages do nothing."** They
  write to `routed` and `shared_output`. The residual is the wrong buffer to watch for
  that question, and no instrument here watches the right one.
- **No timing was measured** and nothing here says any step is removable.
- The MLA/KDA split (24/68), the block period of 12 and the collapse at block writes are
  all in the source. Reproducing them is a check on the walk, not a finding.

### A second correction to my own count

`local 2` moves **0.000 at every offset in every block**. Stage 2 is
`memcpy(sequence->residual, input, …)`, so the record is bit-identical to `local 0`. My
361 measured it against `local 1`, the previous position's leftover, which is why it
appeared to move a median of 22.25.

The reconciliation against the trace is then exact:

```
452 trace hash changes = 92  local 2, measured against the leftover
                       + 269 arithmetic: 92 attention + 85 fold + 92 MoE add
                       + 91  local 120, bookkeeping
```

**269 stages per position change the carried residual by doing arithmetic**, of 9,956
recorded. Three per pod, two at the seven block-write pods.

### Reading

The 12-period is not an event inside a 92-long sequence. It is the unit, and reading by
pod hid three things:

**The fold is governed by block offset, not depth.** Its three largest movements are
exactly the three MLA offsets — 4.330, 4.964, 3.670 against 1.0–3.6 everywhere else.
Nothing in a 92-row table shows that, because the MLA pods are scattered through it.

**Offset 12 folds nothing, in all seven full blocks.** The residual is replaced rather
than added at a block write, so stage 20 leaves it bit-identical. Shown per-offset here;
previously only inferred from the count 85 = 92 − 7.

**A block is close to a no-op in magnitude.** The state swings by 4× to 110× inside a
block and the block hands on roughly 1.38× what it received. The growth is internal and
the block write discards it.

**Routing is not block-structured.** Effective spread runs 6.3 to 16.0 scattered across
the grid with no offset pattern, and the routed/shared ratio likewise. Whatever the block
organises, it is not which experts get chosen — which is worth stating precisely because
everything else on this page is organised by it.

### What this does not establish

Still one prompt, one position. Seven full repeats of a 12-pod block is seven samples,
not a population, and the eighth block is a different length. The ×1.377 geometric mean
is over those seven. Nothing here says a block could be removed, shortened or shared.

## The tree

The creator named the unit as **KDA-KDA-KDA-MLA**. For MLA to be last, groups align to
pod ≡ 3 (mod 4) — (0,1,2,3), (4,5,6,7), … — which puts the server at pod 0 as the first
leaf of the first group rather than a prefix outside the structure.

That re-aligns the block as well. The write condition in the pod source is
`pod % 12 == 0`, so a block runs 12B…12B+11 with the **write at its first pod**. Every
section above this line used pods 1–12 as block 1, which puts the write at the end and
cuts each group in half. 12 = 3 × 4, so the aligned block is exactly three groups.

```
request
|
+- embed(token) ---------------------------------------- fold source 0
|
+- block 0   pods  0-11   write at pod  0  -+- (K K K M)  0  1  2  3   <- pod 0 is the server
|                                           +- (K K K M)  4  5  6  7
|                                           +- (K K K M)  8  9 10 11 -- source 1
+- block 1   pods 12-23   write at pod 12   -- 3 groups -------------- source 2
+- block 2   pods 24-35   write at pod 24   -- 3 groups -------------- source 3
+- block 3   pods 36-47   write at pod 36   -- 3 groups -------------- source 4
+- block 4   pods 48-59   write at pod 48   -- 3 groups -------------- source 5
+- block 5   pods 60-71   write at pod 60   -- 3 groups -------------- source 6
+- block 6   pods 72-83   write at pod 72   -- 3 groups -------------- source 7
+- block 7   pods 84-92   write at pod 84   -- (K K K M)(K K K M)(M) -- source 8
|
+- fold the nine sources -> RMS gain -> project to 163840 -> token

one pod  = 120 stages, 3 of which do arithmetic on the carried state
one moe  = 16 of 896 experts, 80 expert stages writing a separate buffer
```

## Three things in these notes that the capture contradicted

**The pod-to-file mapping.** A new reader written with `pod = owner - 1` dropped 45 of 92
pods and reported no error. The files carrying MLA internals are exactly `{3,7,…,91} ∪
{92}` — the MLA set — so the file index *is* the pod number. `block-census.py` and
`group-walk.py` were already correct; only the new reader was wrong. Any new reader should
assert `rows == 92 × positions` and print the skipped list rather than continue quietly.

**69 KDA.** There are **68** files carrying KDA internals. Files 0 and 93 carry neither
kind — 35 and 13 records, no local 0, no local 6. The earlier note that pod 0 is an
ordinary K with a dense MLP is contradicted by this capture. What those two files are is
not re-established here.

**`rel_attn`.** The twelve-prompt census computes `|attention − incoming| / |incoming|`.
The attention local holds the attention output *alone* and **replaces** the residual, so
that expression subtracts two different things and reads ≈1.0 whenever the attention is
small. At position 4, `|attention| / |input|` spans 0.0050 to 1.6131 while `rel_attn`
spans 0.8632 to 1.6302. The group ordering (K, K, K, M) survives; the magnitudes do not
mean what the column name says, and the "attention spread is only 1.22× across groups"
reading is compressed by the same transform. The obvious correction was tested rather than
assumed: the attention output is **not** orthogonal to the residual (cos −0.4640 to
0.5099, median 0.1857), so `sqrt(1+r²)` is off by up to 0.27 as well.
